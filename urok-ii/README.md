# Курс «Локальный ИИ своими руками»

Четыре урока + финальный проект на зачёт. Всё считается на учебном классе:
**16 ГБ ОЗУ, GeForce RTX 3060 8 ГБ**, Windows/Linux, LM Studio 0.4.x.
Домашних заданий нет — все практики делаются в классе.

Каждый файл самодостаточен: работает без интернета, без внешних библиотек и шрифтов,
открывается двойным щелчком в любом браузере, печатается в PDF.

## Защита от пролистывания (в ученических файлах)

Во всех файлах `index-bez-zametok.html` и в `kurs-uchenik.html` включён
**режим обязательного прохождения**. Ожидания по времени нет — только порядок и два реальных условия.

1. **Слайды открываются строго по порядку.** `End`, цифры `0–9`, колесо мыши, свайп,
   переход по оглавлению вперёд и режим «только практика» отключены — обойти порядок нельзя.
2. **Теоретический слайд** — прочитать и один раз нажать «Далее». Никаких таймеров и прокрутки.
   **При возврате назад слайд уже помечен прочитанным и открывается сразу**, ждать не нужно.
3. **Слайд с практикой** не откроется, пока не отмечены **все пункты чек-листа**.
4. **Тест в конце каждого урока обязателен.** Объяснения к вопросам и переход дальше
   открываются, только когда **все 8 ответов верны**. Ошибся — «Пройти заново» и обратно к слайдам.
5. **Прогресс сохраняется** в браузере: файл можно закрыть и продолжить с того же места.
   Кнопка **«↺ Прогресс»** внизу сбрасывает его двойным щелчком — нужно, когда за компьютер
   садится следующий ученик.

Вверху каждого слайда висит плашка с причиной блокировки, внизу — счётчик вида `12 / 107 · открыто 12`.
Отметил чек-лист — плашка сразу становится зелёной.

### Честно о пределах защиты

Это защита от **невнимательного** пролистывания, а не от взлома: файл лежит у ученика,
и при большом упорстве его можно отредактировать. Что реально обеспечивает контроль:

- прогресс хранится под неочевидным ключом и с контрольной суммой — правка значения
  в `localStorage` откатывает курс в начало;
- тест нельзя сдать наугад: объяснения закрыты до полного успеха;
- на защите финального проекта спрашивают **каждого** участника и не только по его роли;
- преподаватель видит класс и проходит между рядами.

Если нужен жёсткий контроль — выдавайте файлы с учебного сервера в режиме «только чтение»
и принимайте работу на своих машинах.

## Финальный проект (зачёт)

Шесть команд по четыре человека, у каждой своя тема, но **одинаковый обязательный минимум**
из семи пунктов: работает офлайн, общение через API, три инструмента (один свой),
RAG по своим документам, устойчивый стиль, безопасность, обработка ошибок и лог.

Оценка: **100 баллов** (52 за обязательный минимум, 30 за качество продукта, 18 за защиту)
плюс до **20 бонусных**. Порог зачёта — **60 баллов** при закрытом минимуме.
Зачёт личный: вклад каждого подтверждается ответами жюри и анонимной взаимной оценкой.

На защите интернет в классе **выключается** — это проверка пункта «работает локально».

Темы: школьная справочная · репетитор по предмету · органайзер класса ·
обработчик документов · проверка решений · фактчекер-исследователь.

## Тест по уроку 1 (`test-urok-1.html`)

Отдельный файл, не связан со сборкой курса: его можно раздавать самостоятельно.

**Как проходит.** Ученик вводит фамилию и класс → получает случайный вариант
(по умолчанию 15 вопросов из банка в 32, обязательно по одному из каждой из 10 тем) →
отвечает → видит оценку, разбор ошибок и объяснения. Дальше появляется **код результата**:

```
U1|ИВАНОВА ANNA|10Б|2611011104|50291|15|15|187|e7e7e7l777|lg22|kx
```

В коде — имя, класс, дата и время, номер варианта, сколько верно и всего,
затраченное время, отметки по всем темам, идентификатор попытки и контрольная сумма.
Ученик передаёт код преподавателю: записывает на листке, показывает экран крупно
или отправляет в чат. Изменить балл в коде нельзя — не сойдётся контрольная сумма,
такая строка попадёт в таблицу с пометкой «код недействителен».

**Как собирать.** Кабинет преподавателя (вторая вкладка, код доступа по умолчанию `1234`,
меняется в настройках): вставить коды пачкой — по одному в строке, через запятую
или через пробел; разбитые переносами коды тоже распознаются. Дубликаты отбрасываются.
Дальше таблица и выгрузка:

- **CSV** — UTF-8 с BOM и разделителем `;`, Excel открывает как есть;
- **JSON** — для своих скриптов и журналов;
- **печать** — таблица на бумагу;
- **пустой вариант** — тест на лист А4, если компьютеров на всех не хватает
  (печатаются вопросы с клеточками, без ответов);
- **ручной ввод** — если ребёнок писал на бумаге или код потерялся.

Оценка: «5» — 90% и выше, «4» — 75%, «3» — от порога зачёта (по умолчанию 60%, меняется).
Порог, длина варианта и код доступа настраиваются в кабинете и применяются к новым попыткам.

**Где что хранится.** Результаты складываются в `localStorage` того браузера,
где сдавали тест, и видны на вкладке «Результаты на этом компьютере» — оттуда их
можно выгрузить в CSV или скопировать коды одним списком и отправить преподавателю.
Общей базы между машинами нет: сквозной сбор делает преподаватель у себя,
вставляя присланные коды. В архиве видны все попытки, фильтр «только лучший результат»
показывает по одной строке на ученика.

**Сводка по темам.** В кабинете есть блок «Что классу не удалось»: по всем собранным
работам считается процент верных ответов по каждой из 10 тем — видно, что разобрать
перед уроком 2. Темы: установка, модели, квантование, память, лицензии, галлюцинации,
настройки, API, подключение к коду, безопасность.

### Проверка теста

```bash
cd .. && cd tools && npm i jsdom     # один раз
cd ../urok-ii && node test_quiz.js test-urok-1.html
```

159 проверок: прохождение теста в трёх режимах, формат и подделка кода, разбор кодов
из чата, дубликаты, две попытки одного ученика, слабые темы, CSV и JSON, ручной ввод,
настройки, печать, локальный архив, удаление и очистка.

## Портал на школьном сервере (Synology Web Station)

Курс можно раздавать файлами, а можно поставить **портал**: один адрес, регистрация
с паролем, промежуточные тесты после каждого урока и кабинет преподавателя с журналом.

Портал собран под Synology DS223 + Web Station: **PHP 8.1/8.2 + SQLite**, без Docker и Node.js
(DS223 — ARM64 без Container Manager, другого серверного языка там нет).

```
portal/                исходники портала (PHP, JS, CSS, банки вопросов)
build_portal.py        сборка -> dist/kurs-portal.zip (единый архив: kurs/ + инструкция)
dist/kurs-web/         сборка портала (в архиве — папка kurs/), нужна для тестов
dist/kurs-data/        заготовка каталога базы (на NAS его создаёт установщик)
ИНСТРУКЦИЯ-УСТАНОВКА.html  установка на NAS — только GUI, без SSH (вложена в архив)
smoke_portal.py        сквозной прогон: установка → вход → урок → тест → кабинет
test_bridge.js         проверка моста прогресса, встроенного в файлы курса
tests/                 совместимость кода результата и ключа хранилища (JS ↔ PHP ↔ Python)
run_tests.sh           все проверки одной командой
```

Что важно знать:

* **пароли хранятся только в виде хэшей** Argon2id (или bcrypt), проверяются на сервере;
  прочитать их нельзя никому, включая администратора NAS;
* **файлы курса не переписываются** — портал показывает их в iframe и встраивает небольшой мост
  для синхронизации прогресса; офлайн-режим (двойной щелчок) продолжает работать;
* **прогресс у каждого ученика свой** и на сервере, и в браузере: за одним компьютером
  можно входить по очереди;
* **тест проверяется на сервере**: вариант приходит без правильных ответов,
  у соседей разные варианты, результат сразу попадает в журнал;
* есть запасной путь без портала — автономный тест выдаёт код результата,
  который преподаватель вносит пачкой в кабинете (формат кода общий);
* банки вопросов: урок 1 — 32 вопроса / 10 тем, урок 2 — 43 / 9, урок 3 — 36 / 8, урок 4 — 44 / 9.

Установка на NAS — **только через графический интерфейс, без SSH**: откройте
`ИНСТРУКЦИЯ-УСТАНОВКА.html` (вложена в корень `dist/kurs-portal.zip`). Технические
подробности — в `portal/README.md` и `dist/kurs-web/admin/README-DEPLOY.md`.

## Пересборка после правок

```bash
python3 build_teacher.py     # собирает prepod.html и urok-N/_source.html
python3 build_students.py    # собирает index.html и index-bez-zametok.html во всех папках
python3 build_course.py      # собирает kurs-uchenik.html — уроки 1–4 одним файлом, без ожидания
python3 build_portal.py      # собирает портал в dist/ (после правок курса — обязательно)
```

Порядок важен: `build_course.py` использует `_source.html`, который создаёт `build_teacher.py`.

`_source.html` — промежуточный «чистый» урок без методической памятки;
из него строятся обе версии. Править нужно **исходные** `urok-N/index.html`
или сам генератор, иначе пересборка затрёт изменения.

### Проверка сборки

```bash
node test_any.js prepod.html 50          # структура + вся интерактивность любого файла
node test_study.js index-bez-zametok.html 2 3   # режим прохождения (с укороченными таймингами)
node test_course.js kurs-uchenik.html fast      # общий файл: порядок, чек-листы, обязательный тест
node test_study_full.js index-bez-zametok.html  # чек-листы + обязательный тест
python3 urok-N/validate.py               # баланс тегов, тест, отсутствие таймингов и домашки
node test_quiz.js test-urok-1.html       # зачётный тест по уроку 1 (159 проверок)
bash run_tests.sh                        # всё сразу, включая портал (нужны php-cli, node, python3)
python3 smoke_portal.py                  # портал: 117 проверок на встроенном сервере PHP
node test_bridge.js dist/kurs-web/kursy/kurs-uchenik.html speak 107 42   # мост прогресса
python3 tests/test_code_compat.py        # код результата: JS ↔ PHP ↔ Python
python3 tests/test_mix_compat.py         # ключ хранилища прогресса: PHP ↔ JS
```

`build_students.py` берёт шаблоны навигации из `_study_patches.py` —
если меняли скрипт урока, проверьте, что все патчи применяются (`патчей навигации применено: 8 из 8`).
