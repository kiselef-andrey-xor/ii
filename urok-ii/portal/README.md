# Портал курса на Synology Web Station

Один адрес для всего курса: ученик регистрируется с паролем, читает уроки, сдаёт
промежуточные тесты после каждого урока, а преподаватель видит журнал, прогресс класса,
слабые темы и оценки за финальный проект.

Серверная часть — **PHP 8.1/8.2 + SQLite**. Другого выбора на DS223 нет:
это Realtek RTD1615B (ARM64, 2 ГБ ОЗУ), Container Manager на нём не поддерживается,
поэтому ни Docker, ни Node.js-сервера. Web Station умеет статические файлы и PHP — на этом и работаем.

Установка на NAS — **только через графический интерфейс, без SSH**: пошаговая
инструкция `ИНСТРУКЦИЯ-УСТАНОВКА.html` (лежит в корне архива `dist/kurs-portal.zip`,
после сборки копируется в `admin/`). Технические подробности — в
`admin/README-DEPLOY.md` (после сборки попадает в `dist/kurs-web/admin/README-DEPLOY.md`).

## Что видит ученик

`http://NAS/kurs/` → вход или регистрация (фамилия и имя, логин, пароль, класс) → оболочка курса:

* слева — четыре урока, четыре теста и финальный проект со значками «слайд 12 из 107», «тест 13/15 · оценка 4»;
* справа — файл урока. Порядок прохождения сохранён: теорию нужно прочитать и нажать «Далее»,
  в практиках отметить все пункты чек-листа, тест в конце урока открывается только когда все ответы верны;
* следующий урок открывается после зачёта по тесту предыдущего (отключается в кабинете);
* прогресс сохраняется на сервере: можно закрыть браузер, сесть за другой компьютер и продолжить с того же слайда;
* кнопка «Выйти» чистит локальный прогресс — за компьютер может сесть следующий ученик.

## Что видит преподаватель

`http://NAS/kurs/cabinet.php`:

| Вкладка | Что делает |
|---|---|
| **Журнал** | все попытки: фильтр по уроку, классу, фамилии, «только лучший результат»; CSV (UTF-8 BOM, `;`), JSON, список кодов, печать; внесение кодов пачкой из автономного теста; ручной ввод; удаление; очистка |
| **Прогресс** | кто на каком слайде каждого урока, сколько чек-листов закрыто, лучшая оценка, последняя активность |
| **Темы** | процент верных ответов по каждой теме всех четырёх уроков — что разобрать перед следующим занятием |
| **Ученики** | классы, создание аккаунтов, сброс пароля, отключение, признак «сменит пароль при входе» |
| **Финальный проект** | 6 групп × 4 человека: тема, роль, 7 пунктов обязательного минимума, баллы жюри и бонус, зачёт/незачёт |
| **Тест на бумаге** | пустой вариант на лист А4: вопросы с клеточками, без ответов |
| **Настройки** | порог зачёта и длина варианта по каждому уроку, правила портала, смена своего пароля |
| **Диагностика** | версия PHP, расширения, права на каталог данных, банки вопросов, HTTPS, веб-сервер |

### Файлы курса не переписываются

Портал показывает готовые `kurs-uchenik.html`, `urok-N/index-bez-zametok.html`, `final/…`
в iframe. Они остаются самодостаточными: их по-прежнему можно раздать флешкой и открыть
двойным щелчком. Сборщик лишь **встраивает в конец скрипта режима прохождения небольшой мост**
(помечен комментариями `KURS BRIDGE`), который:

1. переходит на отдельный ключ `localStorage` для каждого ученика (`k<id>|x…`), чтобы за одним
   компьютером прогресс не смешивался, и очищает общий ключ;
2. принимает от портала сохранённое состояние параметром `?restore=<json>` и применяет его —
   ученик сразу оказывается на своём слайде, без перезагрузки страницы;
3. раз в несколько секунд сообщает оболочке портала, до какого слайда дошёл ученик.

Без параметра `?uid=` мост молчит — это и есть офлайн-режим.

### Тест

* **Ученик вошёл** — вариант выдаёт сервер, правильные ответы и объяснения в браузер не попадают,
  проверка серверная, попытка сразу ложится в журнал. Вариант привязан к сессии:
  отправить ответы от чужого варианта или отправить тот же вариант дважды не получится.
* **Без входа** (`test.php` открыт напрямую) — тренировочный режим: вариант собирается в браузере
  из публичного банка **без правильных ответов**, результат выдаётся кодом `U2|…|crc`,
  который ученик передаёт преподавателю. Преподаватель вносит коды пачкой в кабинете.
  Это не защита от списывания, а запасной путь, когда портал недоступен.

Формат кода и контрольная сумма — те же, что в автономном `test-urok-1.html`, поэтому коды
из старого теста принимаются кабинетом как есть. Совместимость JavaScript ↔ PHP проверяется
автоматически (`tests/test_code_compat.py`).

## Безопасность

* **Пароли — только хэши.** `password_hash(PASSWORD_ARGON2ID, memory_cost 8192, time_cost 3)`,
  при отсутствии Argon2id — `bcrypt cost 12`. Проверка `password_verify()`, при устаревших
  параметрах хэш автоматически пересчитывается при входе. Хэш не отдаётся клиенту никогда;
  «расшифровать» его нельзя — это необратимое преобразование, а не шифрование.
* **Сессия**: cookie `kursid` с `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS,
  `use_strict_mode`, время жизни 8 часов, регенерация идентификатора после входа.
* **CSRF**: токен в сессии, обязателен в заголовке `X-CSRF-Token` для всех POST.
* **Подбор пароля**: 5 неудач — блокировка аккаунта на 10 минут; отдельный счётчик по IP
  (`ratelimit.json` в каталоге данных); одинаковая задержка ответа, чтобы по времени
  нельзя было узнать существующий логин.
* **Роли** проверяются в каждом обработчике: ученик не видит чужие результаты, журнал,
  настройки и файлы с заметками преподавателя (`course.php` отдаёт ему только ученические версии).
* **База лежит вне веб-корня** (общая папка `kurs-data`, создаётся через GUI Панели
  управления), плюс `.htaccess`-правила (Apache 2.4) на `kursy/`, `banks/`, `lib/`.
* **SQL** — только подготовленные выражения, вывод экранируется, JSON с `JSON_HEX_TAG`.
* **Заголовки**: `X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy`,
  CSP, HSTS при HTTPS.
* **HTTPS**: портал понимает `X-Forwarded-Proto` от обратного прокси Synology
  (отключается в `lib/config.local.php`). Без HTTPS страница входа показывает предупреждение.
* **Персональные данные** детей не покидают NAS: портал не делает внешних запросов,
  не подключает CDN, шрифты и аналитику.
* **Журнал аудита**: входы (успешные и нет), регистрация, сдача тестов, внесение кодов,
  сброс паролей, изменение настроек, удаление записей.

Честное ограничение: защита варианта теста и прогресса — серверная, но сам файл урока лежит
у ученика в браузере, поэтому при большом упорстве его можно отредактировать. Реальный контроль
дают серверный журнал, случайные варианты и защита финального проекта.

## Сборка

```bash
cd urok-ii
python3 extract_u1_bank.py     # банк урока 1 из test-urok-1.html -> banks/u1.json
python3 make_banks.py          # банки уроков 2-4 -> banks/u2..u4.json
python3 build_portal.py        # dist/kurs-web + dist/kurs-portal.zip (единый архив)
```

Если правили сами уроки — сначала штатная цепочка курса, потом портал:

```bash
python3 build_teacher.py && python3 build_students.py && python3 build_course.py
python3 build_portal.py
```

`dist/kurs-portal.zip` — единственный архив для NAS: внутри папка `kurs/` (после
«Извлечь сюда» в `/volume1/web` получается `/volume1/web/kurs`) и
`ИНСТРУКЦИЯ-УСТАНОВКА.html`. `dist/kurs-web` — та же сборка папкой (используют тесты),
`dist/kurs-data` — заготовка каталога данных для локальных проверок. На NAS папку
`kurs-data` создают через «Панель управления → Общая папка», права выдают мышкой
через File Station, а служебные файлы внутри создаёт установщик.

## Проверки

```bash
bash run_tests.sh              # всё сразу
```

по отдельности:

```bash
python3 smoke_portal.py                     # 117 проверок: установка → вход → урок → тест → кабинет
node test_bridge.js dist/kurs-web/kursy/kurs-uchenik.html speak 107 42   # мост прогресса
python3 tests/test_code_compat.py           # код результата: JS ↔ PHP ↔ Python (52 проверки)
python3 tests/test_mix_compat.py            # ключ хранилища: PHP ↔ JS (16 проверок)
node test_quiz.js test-urok-1.html          # автономный тест урока 1 (159 проверок)
node test_course.js dist/kurs-web/kursy/kurs-uchenik.html fast   # режим прохождения после встраивания моста
for f in $(find portal -name '*.php'); do php -l $f; done        # синтаксис PHP
```

Для проверок нужны `php-cli` 8.1+ (с `pdo_sqlite`, `mbstring`), `node` и `python3`;
jsdom ставится так: `cd ../tools && npm i jsdom`.

## Банки вопросов

| Урок | Файл | Вопросов | Тем |
|---|---|---|---|
| 1 · модель говорит | `banks/u1.json` | 32 | 10 |
| 2 · модель действует | `banks/u2.json` | 43 | 9 |
| 3 · модель знает | `banks/u3.json` | 36 | 8 |
| 4 · модель своя | `banks/u4.json` | 44 | 9 |

Формат один и тот же: `{t: тема, q: вопрос, o: [варианты], a: индекс верного, e: объяснение}`.
Вопросы уроков 2–4 составлены по содержанию слайдов этих уроков, поэтому расхождений
с материалом нет. Правите вопрос — правьте `make_banks.py` (или `banks/uN.json` напрямую)
и заново запустите `build_portal.py`.

Вариант собирается так: по одному вопросу из каждой темы, затем добор случайными до нужной
длины; порядок вариантов ответа тоже перемешивается. Поэтому у соседей по парте разные варианты.

## Что делать, если…

| Ситуация | Решение |
|---|---|
| Ученик забыл пароль | Кабинет → «Ученики» → «🔑 Пароль» → задать новый. Ученик сменит его при входе |
| Компьютер один на класс | Каждый ученик входит под своим логином: прогресс хранится под своим ключом и на сервере. Перед следующим учеником — «Выйти» |
| Портал недоступен (нет сети до NAS) | Раздайте файлы курса как раньше и автономный `test-urok-1.html`, затем внесите коды в кабинете пачкой |
| Нужно перенести на другой NAS | Скопируйте папки `web/kurs` и `kurs-data` (File Station), на новом NAS повторите настройку прав: Свойства → Права → `everyone` → Чтение + Запись |
| Хочется посмотреть базу руками | Консоль не нужна: выгрузите журнал в CSV/JSON из кабинета преподавателя, а копию файла `kurs.db` скачайте через File Station |
