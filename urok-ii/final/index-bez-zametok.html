Что нужно сдать

1 · Работающий продукт

Программа, которая решает вашу задачу полностью локально. На защите интернет в классе выключают — это часть проверки.

2 · Демонстрация

5 минут живого показа + 2 минуты вопросов жюри. Отвечают все члены команды, у каждого должен быть свой участок.

3 · Документация

Паспорт системы (одна страница): из чего состоит, как запустить, что умеет, чего не умеет, известные ограничения.

4 · Отчёт об измерениях

10 контрольных примеров с результатами, таблица «до / после», два честно записанных отказа системы.

Главный принцип оценивания: оценивается не «красота ответа», а инженерная работа. Система, которая честно говорит «я этого не знаю» и не падает на ошибке, получит больше баллов, чем эффектная, но непредсказуемая. Мы четыре урока учились измерять и ограничивать — здесь это проверяется.
Сроки: три занятия. Занятие 1 — выбор темы, роли, план, сбор данных. Занятие 2 — сборка и промежуточный контроль. Занятие 3 — дообучение, тесты, документация и защита. Расписание — на слайде 9.
Команда и роли

Кто что делает

Четыре роли — по числу участников. Роль не означает, что остальные не помогают: она означает, кто отвечает за участок и кто про него рассказывает на защите.

🧭 Тимлид · архитектор

  • Держит план и сроки, следит, чтобы обязательный минимум был закрыт
  • Решает, что выкидываем, если не успеваем
  • Отвечает за связность: инструменты, промпты и база знаний не противоречат друг другу
  • Ведёт паспорт системы
  • На защите: общее описание и ответы про архитектуру

📚 Дата-инженер

  • Собирает документы для базы знаний и датасет для дообучения
  • Режет текст на чанки, подбирает размер и перекрытие, строит индекс
  • Проверяет данные вручную: без мусора, без личных данных, без чужого авторства
  • Отвечает за качество поиска: проверяет, что нужный фрагмент попадает в топ-3
  • На защите: откуда данные, как проверяли, что не взяли и почему

⚙️ Разработчик

  • Пишет код: цикл агента, реестр инструментов, запросы к API
  • Делает интерфейс (консоль, веб-страница или Telegram-бот)
  • Настраивает параметры модели и системный промпт
  • Запускает дообучение и экспорт в GGUF
  • На защите: показывает код и объясняет, как он устроен

🛡 Тестировщик · безопасник

  • Составляет 10 контрольных примеров и таблицу «до / после»
  • Ломает систему намеренно: пустой ввод, отсутствующий факт, инъекция промпта, несуществующая команда
  • Проверяет, что опасные действия спрашивают подтверждение
  • Пишет раздел «известные ограничения» — честно
  • На защите: показывает тесты и найденные проблемы

🛠 Распределить роли (занятие 1, первые 10 минут)

Правило взаимозаменяемости: каждый должен понимать работу соседа настолько, чтобы ответить на вопрос жюри по любому участку. На защите спросить могут любого — и это влияет на личный зачёт (слайд 8).
Обязательно для всех шести команд

Обязательный минимум архитектуры

Темы разные, каркас один. Эти семь пунктов должны быть у всех — без них зачёт не выставляется, сколько бы баллов ни набрала команда.

① Полностью локально

Модель работает на вашем компьютере через LM Studio. На защите интернет отключается, и система продолжает работать. Облачные API запрещены.

② Общение через API

Ваша программа обращается к модели по http://localhost:1234/v1, а не через окно чата. То есть это ваш код, а не переписка вручную.

③ Минимум три инструмента

Через tool calling или MCP. Хотя бы один — свой собственный, написанный вами, а не взятый готовым плагином.

④ База знаний (RAG)

Свои документы → нарезка на чанки → эмбеддинги → поиск по смыслу → ответ строго по найденному. Модель умеет сказать «в базе знаний этого нет».

⑤ Заданное поведение

Устойчивый стиль и формат ответов: через System Context или через дообученную модель (LoRA). Должно держаться на всех ответах, а не на одном.

⑥ Безопасность

Песочница для файлов, белый список команд, подтверждение человека для опасных действий, лимит шагов агента, секреты вне контекста модели.

⑦ Обработка ошибок и лог

Система не падает на: пустом вводе, вопросе не по теме, отсутствующем факте, сломанном инструменте, незапущенном сервере. В каждом случае выдаёт понятное сообщение. Каждый вызов инструмента пишется в лог — на защите вы покажете его жюри.

Как проверяем пункт ①: перед защитой преподаватель выключает в классе Wi-Fi (или переводит ПК в режим «в самолёте»). Команда запускает систему и демонстрирует работу. Не запустилось без сети — пункт не засчитан.
Почему каркас общий: так честно сравнивать команды. Темы разные, сложность разная, но проверяются одни и те же навыки, пройденные на четырёх уроках: API, инструменты, RAG, настройка поведения, безопасность, измерения.
Шесть тем — по одной на команду

Темы 1–3

Каждая тема закрывает обязательный минимум, но добавляет свои требования. Их проверяют отдельно (слайд 6).

Команда 1 · 🏫 Школьная справочная

Продукт: система, которая отвечает на вопросы учеников и родителей по уставу школы, правилам, расписанию и списку кружков.

Интерфейс: веб-страница (как в уроке 1, практика 13) или Telegram-бот.

Свои инструменты: «текущее время и день недели», «какой сейчас урок по расписанию», «найти кабинет по номеру».

Стиль: вежливо, официально, кратко, без панибратства. Ответ всегда заканчивается ссылкой на источник в документах.

Особое требование: на вопрос, которого нет в документах, система отвечает «этого нет в правилах школы, уточните в секретариате» — и не придумывает. Проверяется тремя провокационными вопросами.

Команда 2 · 🎓 Репетитор по предмету

Продукт: помощник, который объясняет тему по учебнику и не выдаёт готовый ответ, а подводит к нему вопросами.

Интерфейс: консоль или веб-страница с историей разговора.

Свои инструменты: «калькулятор», «сгенерировать 5 тренировочных задач по теме», «проверить ответ ученика».

Стиль: терпеливый, простой язык, примеры из жизни, один вопрос в конце каждого ответа. Можно закрепить дообучением.

Особое требование: при прямом вопросе «просто скажи ответ» репетитор отказывается и предлагает подсказку. Проверяется на трёх разных задачах.

Команда 3 · 📅 Органайзер класса

Продукт: помощник классного руководителя: расписание, дедлайны, список дел, заметки по урокам.

Интерфейс: Telegram-бот (урок 1, практика 14) с долгой памятью (урок 3, практика 7).

Свои инструменты: «сегодняшняя дата», «сколько дней до события», «прочитать файл заметок», «дописать строку в файл» — последнее только с подтверждением.

Стиль: коротко, списками, без воды. Формат «что · когда · кто».

Особое требование: память переживает перезапуск — на защите бота перезапускают и спрашивают про вчерашнюю договорённость.

Шесть тем — по одной на команду

Темы 4–6

Команда 4 · 🧾 Обработчик документов

Продукт: превращает неструктурированный текст в данные. Объявление, чек, описание товара, резюме → аккуратный JSON по вашей схеме.

Интерфейс: веб-страница: поле для текста, кнопка, таблица с результатом и выгрузка в CSV.

Свои инструменты: «прочитать файл из папки», «посчитать сумму и среднее по списку», «сохранить результат в CSV» — с подтверждением.

Стиль: строгий вывод по JSON Schema (урок 1, практика 9). Никакого текста вокруг JSON.

Особое требование: из 10 тестовых документов минимум 8 разбираются без ошибок, а в остальных система честно сообщает, какое поле не удалось извлечь. Пакетная обработка всей папки — бонус.

Команда 5 · ✅ Проверка решений

Продукт: принимает решение задачи по математике или физике, проверяет его по шагам и указывает на конкретную ошибку.

Интерфейс: консоль или веб-страница с двумя полями: «условие» и «решение ученика».

Свои инструменты: «калькулятор» (обязательно — модель не должна считать в уме), «найти правило в справочнике» (RAG по формулам), «сохранить разбор в файл».

Стиль: разбор по шагам: что верно → где ошибка → как исправить → ответ. Без готового решения в лоб.

Особое требование: на 10 решениях с заранее известными ошибками система находит ошибку минимум в 7. Ошибочные ответы считает калькулятором, а не «в уме» — это видно в логе.

Команда 6 · 🔎 Фактчекер-исследователь

Продукт: собирает материал по теме из локальных источников (свои конспекты, скачанные статьи), делает выжимку с указанием источника и помечает спорные места.

Интерфейс: консольный агент с логом шагов или веб-страница со списком источников.

Свои инструменты: «поиск по базе знаний», «прочитать файл», «записать вывод в отчёт», «посчитать, сколько источников использовано».

Стиль: каждый факт сопровождается ссылкой на источник: [фрагмент 12, conspect.txt]. Без источника — фраза помечается как «требует проверки».

Особое требование: агент делает несколько шагов (минимум три вызова инструментов) и не выдумывает источники. Отдельно демонстрируется защита от инъекции: в один из документов намеренно вставлена вредная инструкция — агент не должен её выполнить.

Личный вклад

Зачёт индивидуальный, а проект общий

Команда получает одну оценку за систему. Но зачёт каждый получает лично — по своему вкладу и по ответам жюри.

Как считаем личный вклад

  1. Оценка жюри (0–3): насколько уверенно человек отвечал на вопросы по своему участку и по соседним
  2. Взаимная оценка (0–3): каждый анонимно оценивает вклад остальных троих
  3. Артефакты: чей код в репозитории, кто заполнял таблицу замеров, кто вёл паспорт системы

Итог: 0 баллов — личный зачёт не выставлен, даже если команда набрала 90. 1–2 — зачёт. 3 — зачёт с отличием.

Правило «спросят любого»

Жюри задаёт минимум четыре вопроса — по одному каждому участнику, причём не только по его роли:

  • тимлиду — про данные или тесты
  • дата-инженеру — про код инструмента
  • разработчику — про качество поиска
  • тестировщику — про ограничения системы

Это делает «пассажиров» видимыми и заставляет команду реально работать вместе.

Регламент защиты

Как проходит защита

Порядок

  1. Команды сдают файлы преподавателю за 10 минут до начала
  2. Преподаватель отключает интернет в классе
  3. Жеребьёвка порядка выступлений
  4. На команду: 5 минут демонстрация + 2 минуты вопросы + 1 минута обратная связь
  5. Остальные команды в это время заполняют лист наблюдения (ниже)
  6. В конце — анонимная взаимная оценка внутри каждой команды
  7. Объявление баллов сразу после всех защит

Состав жюри

  • Преподаватель — основной оценщик
  • Два представителя от других команд — по ротации, оценивают только критерий «удобство» и «понятность демонстрации»

Ротация: пока защищает команда 1, в жюри сидят представители команд 2 и 3; команду 2 оценивают 3 и 4, и так далее. Так никто не судит сам себя.

Жюри-ученики ставят баллы по двум критериям части 3, преподаватель — по остальным.

Правило «сначала скелет, потом мясо»: к концу первого занятия у команды должен работать примитивный сквозной путь: запрос → поиск по базе → один инструмент → ответ. Пусть кривой и некрасивый. Дальше его наращивают. Команды, которые сначала две недели «пишут красивый интерфейс», обычно не доходят до защиты.
Что сдаём преподавателю до защиты: папку с кодом, датасетом, индексом, паспортом системы и таблицей замеров — за 10 минут до начала. Плюс запасную видеозапись демонстрации на случай технической аварии (не оценивается, но спасает команду).

Минимальный каркас системы (скелет, который должен заработать первым)

"""Каркас финального проекта: запрос -> поиск по базе -> инструмент -> ответ."""
import json, os
from openai import OpenAI

client = OpenAI(base_url="http://localhost:1234/v1", api_key="lm-studio")
CHAT   = "qwen/qwen3-8b"                             # ← чат-модель
EMBED  = "text-embedding-qwen3-embedding-0.6b"       # ← эмбеддинги
MAX_STEPS = 6

# --- 1. своя база знаний (из урока 3) ---
def search(question, top_k=3):
    """Вернуть топ-K фрагментов из index.json по смыслу."""
    import math
    qv = client.embeddings.create(model=EMBED, input=question).data[0].embedding
    data = json.loads(open("index.json", encoding="utf-8").read())
    def cos(a, b):
        d = sum(x*y for x, y in zip(a, b))
        na = math.sqrt(sum(x*x for x in a)); nb = math.sqrt(sum(y*y for y in b))
        return d / (na * nb) if na and nb else 0.0
    ranked = sorted(((cos(qv, d["vector"]), d) for d in data),
                    key=lambda t: t[0], reverse=True)
    return [(round(s, 3), d["text"]) for s, d in ranked[:top_k]]

# --- 2. свой инструмент (из урока 2) ---
def now() -> str:
    """Текущая дата и время."""
    from datetime import datetime
    return datetime.now().strftime("%Y-%m-%d %H:%M")

REGISTRY = {"now": now, "search_kb": lambda query: json.dumps(search(query), ensure_ascii=False)}
TOOLS = [
  {"type": "function", "function": {"name": "now",
    "description": "Узнать текущие дату и время.",
    "parameters": {"type": "object", "properties": {}}}},
  {"type": "function", "function": {"name": "search_kb",
    "description": "Поиск по базе знаний проекта. Вызывай для ЛЮБОГО вопроса по теме.",
    "parameters": {"type": "object", "properties": {"query": {"type": "string"}},
                   "required": ["query"], "additionalProperties": False}}},
]

SYSTEM = ("Ты — помощник проекта. Отвечай только по данным из базы знаний. "
          "Если поиск не дал нужного — честно скажи, что этого нет в базе. "
          "Не выдумывай факты, числа и источники. Отвечай кратко, по-русски.")

# --- 3. цикл агента ---
def run(task):
    messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": task}]
    for step in range(1, MAX_STEPS + 1):
        r = client.chat.completions.create(model=CHAT, messages=messages,
                                          tools=TOOLS, temperature=0.2, max_tokens=600)
        msg = r.choices[0].message
        if not msg.tool_calls:
            print("ОТВЕТ:", msg.content)
            return
        messages.append(msg.model_dump())
        for tc in msg.tool_calls:
            args = json.loads(tc.function.arguments or "{}")
            fn = REGISTRY.get(tc.function.name)
            try:
                result = fn(**args) if fn else "нет такого инструмента"
            except Exception as exc:
                result = "ошибка инструмента: %s" % exc
            print("  шаг %d: %s%s -> %s" % (step, tc.function.name, args, str(result)[:120]))
            messages.append({"role": "tool", "tool_call_id": tc.id, "content": str(result)})
    print("превышен лимит шагов")

run("Ваш вопрос по теме проекта")
