# Установка портала на Synology DS223 (Web Station) — только GUI, без SSH

Портал — это **статические файлы + PHP 8 + база SQLite**. Никаких контейнеров и Node.js:
DS223 (Realtek RTD1615B, ARM64) Container Manager не поддерживает, поэтому серверная часть
написана на PHP, который Web Station умеет из коробки.

Все шаги выполняются в графическом интерфейсе DSM (браузер): Центр пакетов,
Панель управления, File Station, Web Station. Терминал и SSH не нужны.
Краткая версия для печати — `ИНСТРУКЦИЯ-УСТАНОВКА.html` (в корне архива и в этой папке).

Дальше по тексту:

* `NAS` — ваш Synology DS223;
* `/volume1/web/kurs` — папка портала (веб-корень);
* `/volume1/kurs-data` — папка с базой данных (**вне** веб-корня).

---

## 1. Что установить в DSM

Центр пакетов → установить:

| Пакет | Зачем |
|---|---|
| **Web Station** | веб-сервер и порталы |
| **PHP 8.2** (или 8.1) | серверный язык портала. PHP 7.3/7.4/8.0 сняты с поддержки Synology |

MariaDB не нужна: портал работает на SQLite.

### Настроить профиль PHP

Web Station → **Настройки сценария (Script Language Settings)** → профиль PHP 8.2 →
**Extensions**: включите

* `pdo_sqlite` — обязательно (база данных);
* `sqlite3` — обязательно;
* `mbstring` — обязательно (русские имена);
* `openssl`, `curl`, `json`, `hash`, `session`, `pcre` — обычно включены по умолчанию.

Там же проверьте **open_basedir**: если он задан, в него нужно добавить `/volume1/kurs-data`,
иначе PHP не сможет открыть файл базы. Проще всего оставить open_basedir пустым
или указать `/volume1/web:/volume1/kurs-data:/tmp`.

## 2. Создать папки и залить файлы

### Папка портала (File Station)

1. Откройте общую папку `web` (её создал пакет Web Station: `/volume1/web`).
2. Загрузите в неё архив **`kurs-portal.zip`** (кнопка «Загрузка» или перетаскиванием).
3. Правый клик на архиве → **Извлечь** → **«Извлечь сюда»**.
   В архиве папка уже называется `kurs` — получится `/volume1/web/kurs`, переименовывать
   ничего не нужно. Внутри должны быть `index.php`, `login.php`, папки `api`, `kursy`, `banks`.
4. Распакованный рядом файл `ИНСТРУКЦИЯ-УСТАНОВКА.html` можно оставить или удалить;
   сам архив после распаковки можно удалить.
5. Отображение скрытых файлов (`.htaccess`) включается так:
   File Station → Настройки → показать скрытые файлы.

### Папка данных и права на неё (мышкой, без консоли)

1. **Панель управления → Общая папка → Создать**: имя **`kurs-data`**, том Volume 1,
   без шифрования. Папка окажется **вне** сайта (`/volume1/kurs-data`) — у неё нет
   веб-адреса, скачать базу по ссылке нельзя.
2. **File Station → правый клик на `kurs-data` → Свойства → Права → Создать**:
   * пользователь или группа: **`everyone`** (если её нет в списке — группа **`http`**:
     это пользователь, под которым работает веб-сервер DSM);
   * права: **Чтение** и **Запись**;
   * отметьте **«Применить к этой папке, подпапкам и файлам»** → Готово → Сохранить.
3. Копировать в `kurs-data` ничего не нужно: при установке `admin/install.php`
   сам создаст там базу `kurs.db`, а также служебные `.htaccess` и `README.md`.

Самой папке портала `web/kurs` особые права не требуются: портал ничего не пишет
внутри себя — всё изменяемое лежит в `kurs-data`.

## 3. Создать портал в Web Station

Web Station → **Веб-служба (Web Service)** → **Создать** → **Портал на основе папки
(Folder-based portal)**:

| Поле | Значение |
|---|---|
| Имя | `kurs` |
| Описание | Курс «Локальный ИИ своими руками» |
| Документ-корень | `/web/kurs` |
| Профиль PHP | **PHP 8.2** |
| Сервер | Apache HTTP Server 2.4 (проще: работают `.htaccess`) |

Если вы используете nginx — правила закрытия каталогов см. в разделе 6.

Если имя хоста оставить пустым, DSM назначит порталу выделенный порт и покажет его
в списке веб-служб (например, `8080`) — адрес портала будет `http://NAS:8080`.
Если указать имя хоста (свой домен) — портал будет отвечать по нему.
Запишите адрес: он понадобится для проверок, и его получат ученики.
Если порт закрыт: Панель управления → Безопасность → Брандмауэр → разрешите порт портала.

## 4. Первая установка

1. Откройте `http://NAS/kurs/admin/install.php`.
2. Страница покажет проверку окружения: версия PHP, `pdo_sqlite`, права на каталог данных,
   банки вопросов, файлы курса, HTTPS. Все пункты должны быть зелёными — иначе портал
   не заработает, и в таблице написано, что сделать.
3. Задайте **пароль преподавателя** (он сразу превращается в хэш Argon2id или bcrypt
   и записывается в базу — прочитать его потом нельзя никому, включая администратора NAS),
   фамилию и имя, первый класс и порог зачёта.
4. Нажмите «Установить».
5. **Переименуйте `admin/install.php`** в `admin/install.php.off`:
   File Station → `web/kurs/admin` → правый клик → Переименовать.
6. Откройте `…/api/index.php?a=health` (подставьте адрес своего портала) —
   все проверки должны быть зелёными.
7. Войдите как преподаватель → **Кабинет** → «Ученики»: создайте классы и, если нужно,
   аккаунты; либо оставьте включённой самостоятельную регистрацию.

---

## 5. Адрес, который давать ученикам

```
http://NAS/kurs/
```

Ученик попадает на страницу входа, переходит на вкладку **«Регистрация»**, вводит фамилию
и имя, придумывает логин и пароль, указывает класс — и сразу попадает в курс.

Если самостоятельная регистрация не нужна: кабинет → «Настройки» → снимите галочку
«Ученики могут зарегистрироваться сами», и создавайте аккаунты сами (ученик сменит
временный пароль при первом входе).

## 6. Закрыть служебные каталоги

В портале уже лежат файлы `.htaccess` (рассчитаны на Apache 2.4):

| Файл | Что закрывает |
|---|---|
| `kursy/.htaccess` | файлы уроков: их отдаёт `course.php` после проверки входа |
| `banks/.htaccess` | банки вопросов **с ответами** |
| `lib/.htaccess` | PHP-библиотеки |
| `kurs-data/.htaccess` | база данных (на случай, если её положили внутрь веб-корня) |

Проверьте, что прямой доступ закрыт — просто откройте адреса в браузере:

| Адрес | Ожидание |
|---|---|
| `http://АДРЕС:ПОРТ/kursy/prepod.html` | **403 Forbidden** |
| `http://АДРЕС:ПОРТ/banks/u1.json` | **403 Forbidden** |
| `kurs-data/kurs.db` | веб-адреса нет вообще (папка вне сайта) |

Если вместо 403 отдаётся содержимое — портал работает не на Apache:
Web Station → Веб-служба → выбрать портал → Изменить → веб-сервер
**Apache HTTP Server 2.4**. Для порталов Web Station на Apache `AllowOverride All`
включён по умолчанию, отдельно настраивать его не нужно.

### Портал должен работать на Apache 2.4

Защитные правила портала лежат в `.htaccess`, а nginx их игнорирует; настроить
эквивалентные правила nginx можно только через консоль, поэтому в рамках установки
«только GUI» nginx не поддерживается. Если портал создан с веб-сервером nginx —
измените его: Web Station → Веб-служба → выбрать портал → Изменить →
веб-сервер **Apache HTTP Server 2.4**.

## 7. HTTPS (настоятельно рекомендуется)

Вы писали, что сертификат и обратный прокси уже настроены — тогда проверьте два момента.

1. **Портал должен понимать, что он за HTTPS.** Иначе cookie сессии не получит флаг `Secure`.
   Обратный прокси Synology должен передавать заголовок `X-Forwarded-Proto`.
   Проверка: откройте `api/index.php?a=health` — пункт «HTTPS» должен быть «да».
   Если «нет», а в браузере замок закрыт, значит прокси не передаёт заголовок;
   добавьте его в правиле обратного прокси (DSM → Панель управления → Внешний доступ →
   Обратный прокси → пользовательские заголовки).
   При желании это поведение отключается в `lib/config.local.php`:
   `define('KURS_TRUST_PROXY_PROTO', false);`
2. **Сайт портала должен быть привязан к hostname прокси**, а не к пути. Если портал
   открывается по адресу `https://school.ru/kurs/`, проверьте, что `X-Forwarded-Host`
   не ломает ссылки: портал строит их от `SCRIPT_NAME`, поэтому подпапка работает.

Без HTTPS страница входа показывает жёлтое предупреждение — это не ошибка, а напоминание.

## 8. Где что лежит и как это копировать

| Путь | Содержимое | Копировать? |
|---|---|---|
| `/volume1/web/kurs` | PHP, JS, CSS, файлы курса, банки вопросов | да (это сам портал) |
| `/volume1/kurs-data` | `kurs.db` — аккаунты, прогресс, результаты, аудит | **да, это главное** |

Hyper Backup: добавьте обе папки (или копируйте папку `kurs-data` средствами
File Station — правый клик → «Копировать»). Перенос на другой NAS = скопировать
две папки и повторить настройку прав через File Station (раздел 2).

База — обычный файл SQLite. Смотреть её руками через консоль не нужно (и не
предлагается): все отчёты выгружаются из кабинета преподавателя в CSV/JSON,
а копию файла `kurs.db` для разбора можно скачать тем же File Station.

## 9. Обновление портала

1. Скопируйте `/volume1/kurs-data` в резервную копию.
2. Загрузите новую сборку `kurs-web` поверх `/volume1/web/kurs`.
   Файл `lib/config.local.php`, если вы его создавали, перезаписывать не нужно —
   в новой сборке его нет.
3. Откройте `api/index.php?a=health`.

Схема базы обновляется сама (создание недостающих таблиц), данные не теряются.

## 10. Если что-то не работает

| Симптом | Причина и лечение |
|---|---|
| `500 Internal Server Error` | Посмотрите `error_log` рядом с `index.php` или журнал в Web Station. Чаще всего — нет `pdo_sqlite` или закрыт `open_basedir` |
| «Каталог данных недоступен для записи» | Не выданы права на папку `kurs-data` через File Station (раздел 2): Свойства → Права → `everyone` → Чтение + Запись |
| Пустая страница | В профиле PHP включите `display_errors` на время отладки, либо смотрите `error_log` |
| Ученик видит «Этот раздел пока закрыт» | Так и задумано: урок открывается после зачёта по тесту предыдущего. Отключается в кабинете → «Настройки» |
| Прогресс не сохраняется | Смотрите надпись под списком уроков слева. Обычно это значит, что браузер блокирует localStorage (приватный режим) или `POST api/index.php?a=progress` не проходит — проверьте CSRF и сессию |
| Тест не открывается | `api/index.php?a=health`: банки вопросов должны быть `U1=32, U2=43, U3=36, U4=44` |
| CSV открывается в Excel «кракозябрами» | Не должно: выгрузка идёт в UTF-8 с BOM и разделителем `;`. Если у вас другой Excel — используйте JSON |

Диагностика одним запросом:

```
http://NAS/kurs/api/index.php?a=health
```

## 11. Безопасность: коротко для администрации

* Пароли хранятся **только в виде хэшей** Argon2id (или bcrypt, если Argon2id нет в профиле PHP),
  с автоматическим пересчётом при входе, если параметры устарели.
* Сессия: cookie `kursid` с флагами `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS,
  `session.use_strict_mode`, время жизни 8 часов, регенерация ID после входа.
* Все POST-запросы защищены токеном CSRF.
* Подбор пароля ограничен: 5 неудач — блокировка аккаунта на 10 минут,
  плюс отдельный счётчик по IP на каталог данных (`ratelimit.json`).
* Все SQL-запросы — подготовленные выражения, вывод экранируется.
* Роль проверяется в каждом обработчике: ученик не может читать чужие результаты
  и версии файлов с заметками преподавателя.
* Вариант теста выдаётся **без правильных ответов**; проверка — на сервере.
* Каждый вход, сброс пароля, изменение настроек и удаление записи пишутся в таблицу `audit`.
* Персональные данные детей не покидают NAS: портал не делает внешних запросов
  и не подключает сторонние библиотеки или шрифты.
