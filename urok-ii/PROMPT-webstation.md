## ЗАДАЧА

Собрать **один веб-портал курса «Локальный ИИ своими руками»**, который преподаватель загружает
в Web Station на Synology DS223 и открывает по адресу вида `http://nas-ip/kurs/`. Ученик заходит
один раз (регистрация с паролем), проходит все 4 урока + финальный проект в браузере, сдаёт
промежуточные тесты после каждого урока, а преподаватель видит всё в своём кабинете: кто сколько
прошёл, какие оценки, какие темы западают, выгрузка в CSV.

**Пароли (и учеников, и преподавателя) хранить только в виде криптографических хэшей на сервере.**
Пароль преподавателя в клиентском JS не хранить ни в каком виде — проверка только серверная.

## ЖЁСТКИЕ ОГРАНИЧЕНИЯ ПЛАТФОРМЫ (проверено, не спорь с ними)

1. **DS223** = Realtek RTD1615B, ARM64 (aarch64), 2 ГБ ОЗУ, без аппаратного шифрования.
   **Container Manager (Docker) не поддерживается**, Node.js/Python-серверов в фоне — нет.
   ⇒ Единственный серверный язык: **PHP через Web Station**. Никакого Node-бэкенда, никаких воркеров.
2. Web Station поддерживает статический хостинг + PHP-профили. PHP 7.3/7.4/8.0 объявлены EOL
   (Synology, 14.08.2025) ⇒ целевой профиль **PHP 8.1 или 8.2** (в DSM 7.2/7.3 доступны, на DS223 тоже).
3. БД: **SQLite через PDO** (`pdo_sqlite`). Не требовать установки MariaDB — SQLite это один файл,
   его удобно бэкапить Hyper Backup и копировать на флешку. MariaDB — только как опция в конфиге.
4. На ARM-насосах всё должно работать быстро: никаких тяжёлых зависимостей, Composer не использовать —
   только файлы, которые можно залить одной папкой через File Station.
5. Всё фронтенд-взаимодействие — обычный `fetch()` с JSON; никаких WebSocket/SSE (Web Station их
   нормально не проксирует без доп. настройки).
6. Код портала — **полностью автономный, без интернета**: без CDN, без внешних шрифтов, без аналитики.
   Школьная сеть может быть изолирована.
7. Интерфейс на русском, кодировка UTF-8 везде (HTML `charset`, PHP `mb_internal_encoding`,
   заголовки, CSV с BOM и разделителем `;` — как уже сделано в `test-urok-1.html`).

## АРХИТЕКТУРА

### Общая схема

```
Ученик → http://nas/kurs/            (портал: вход, уроки в iframe, тесты, мой прогресс)
Препод → http://nas/kurs/?cabinet    (кабинет: журнал, статистика, настройки, выгрузки)
            ↓ fetch JSON (same-origin, сессия в cookie)
        api/*.php  →  SQLite (файл ВНЕ веб-корня)
        курсы/*.html (статика, отдаётся как есть)
```

**Принцип «одна страница»:** портал — это `index.php` (или `index.html` + `app.js`), который после входа
показывает оболочку: слева список уроков/тестов с прогрессом, справа — **iframe** с нужным файлом курса.
Существующие файлы (`kurs-uchenik.html`, `urok-N/index-bez-zametok.html`, `final/…`) не перерабатываются —
они остаются самодостаточными и продолжают работать двойным щелчком офлайн. iframe нужен именно для того,
чтобы не схлопнулись их скрипты и их `localStorage`.

### Дерево файлов для загрузки на NAS

```
web/kurs/                      ← Document root портала (например /web/kurs)
  index.php                    ← вход + оболочка портала (роутинг по ?r=…)
  login.php                    ← страница входа/регистрации (отдаётся и без сессии)
  app.js, app.css              ← оболочка: меню, iframe, синхронизация, «мой прогресс»
  test.php                     ← универсальная страница теста (?u=1..4), движок из test-urok-1.html
  api/
    session.php  progress.php  register.php  login.php  logout.php
    tests.php    results.php   teacher.php   admin.php  health.php
  lib/
    db.php        (PDO SQLite, миграции, WAL)
    auth.php      (password_hash/verify, сессии, CSRF, лимит попыток, роли)
    resp.php      (json-ответы, ошибки, заголовки no-store для API)
    export.php    (CSV/JSON/печать)
  kursy/
    kurs-uchenik.html  prepod.html  test-urok-1.html
    urok-1/… urok-2/… urok-3/… urok-4/… final/…
  admin/
    install.php  (первичная установка: проверка PHP/расширений/прав, создание БД и админа)
    README-DEPLOY.md
data/kurs.db                   ← ВНЕ веб-корня (например /kurs-data/kurs.db), см. «Безопасность»
```

### База данных (SQLite, WAL, миграции идемпотентные)

```sql
settings(key TEXT PRIMARY KEY, value TEXT);
-- pass_hash_teacher, min_pass_len, attempts_lock, test_thresholds(json), variant_len(json),
-- open_final_project(0/1), require_https_warning, school_name

classes(id INTEGER PK, name TEXT UNIQUE, join_code TEXT UNIQUE, active INT DEFAULT 1);
-- join_code — короткий код класса, по которому ученик регистрируется сам

users(id INTEGER PK, login TEXT UNIQUE COLLATE NOCASE, name TEXT, class_id INT REFERENCES classes,
      pass_hash TEXT, role TEXT CHECK(role IN ('student','teacher')),
      created_ts INT, last_login_ts INT, failed_logins INT DEFAULT 0, locked_until INT DEFAULT 0,
      must_change_pass INT DEFAULT 0, active INT DEFAULT 1);

progress(user_id INT, lesson TEXT, unlocked INT, visited TEXT /*json*/, position INT,
         tasks_done INT, tasks_total INT, updated_ts INT, sig TEXT,
         PRIMARY KEY(user_id, lesson));
-- sig = HMAC-SHA256(строка состояния, ключ из settings) — вместо клиентской mix()

test_banks(id INTEGER PK, lesson TEXT, topic TEXT, question TEXT, options TEXT /*json*/,
           answer INT, explanation TEXT, weight INT DEFAULT 1, active INT DEFAULT 1);
-- сюда переносится BANK из test-urok-1.html и новые банки уроков 2–4

attempts(id INTEGER PK, user_id INT, lesson TEXT, variant_no INT, question_ids TEXT /*json*/,
         answers TEXT /*json*/, right_cnt INT, total INT, sec INT, score_pct REAL, grade INT,
         per_topic TEXT /*json*/, code TEXT, crc TEXT, ts INT, source TEXT /*'web'|'paste'|'manual'*/,
         UNIQUE(user_id, lesson, code));

final_projects(group_no INT, theme TEXT, member_id INT, role TEXT, self_note TEXT,
               jury_score INT, peer_score INT, min_items TEXT /*json 7 пунктов*/, total INT,
               passed INT, ts INT, PRIMARY KEY(group_no, member_id));

audit(ts INT, actor_id INT, action TEXT, details TEXT);
```

Индексы: `attempts(user_id, lesson)`, `attempts(ts)`, `progress(user_id)`.

### API (все ответы `{"ok":true,…}` / `{"ok":false,"error":"…"}`)

| Метод | Путь | Что делает |
|---|---|---|
| POST | `api/register.php` | `{name, login, password, join_code}` → создание ученика; пароль ≥ 6 символов; логин латиницей/цифры; дубли отклоняются с внятной ошибкой |
| POST | `api/login.php` | `{login, password}` → `password_verify`; 5 неудач → блокировка на 10 минут; выдаёт сессионную cookie |
| POST | `api/logout.php` | уничтожение сессии |
| GET | `api/session.php` | `{role, name, class, progress[], attempts[]}` — для отрисовки оболочки |
| POST | `api/progress.php` | `{lesson, unlocked, visited, position, tasks_done}` → upsert + пересчёт `sig` |
| GET | `api/progress.php?lesson=` | восстановление прогресса при входе (приоритет: сервер → локальный `localStorage`) |
| GET | `api/tests.php?u=2` | вариант теста для залогиненного ученика: N вопросов по всем темам урока, **без правильных ответов и без объяснений** |
| POST | `api/tests.php` | `{u, answers[]}` → сервер проверяет, считает %, оценку, `per_topic`, пишет `attempts`, возвращает разбор + код результата (формат как в `test-urok-1.html`, префикс `U2/U3/U4`) |
| GET | `api/results.php` | журнал (роль teacher): все попытки, фильтр «лучшая попытка», слабые темы |
| GET | `api/teacher.php?r=stats` | сводка по классу: % по каждой теме всех 4 уроков, прогресс по слайдам, кто застрял |
| POST | `api/teacher.php` | смена порога/длины варианта, сброс пароля ученику, отчисление/блокировка, импорт кодов пачкой (совместимость с офлайн-режимом), ручной ввод результата, оценки финального проекта |
| GET | `api/export.php?f=csv\|json` | выгрузка журнала (CSV: UTF-8 BOM, `;`) |
| GET | `api/health.php` | диагностика: версия PHP, наличие `pdo_sqlite`/`sodium`, запись в каталог БД, права, HTTPS или нет |

Все POST защищены токеном CSRF (в сессии + заголовок `X-CSRF-Token`). Все запросы — только same-origin.

## БЕЗОПАСНОСТЬ (это главное требование пользователя)

1. **Хэширование паролей — серверное, PHP:**
   ```php
   $hash = password_hash($pass, PASSWORD_ARGON2ID, ['memory_cost'=>65536,'time_cost'=>4,'threads'=>1]);
   // если ARGON2ID недоступен в профиле PHP (проверить в api/health.php):
   $hash = password_hash($pass, PASSWORD_BCRYPT, ['cost'=>12]);
   // проверка всегда:
   if (password_verify($pass, $hash)) { if (password_needs_rehash($hash, …)) { /* пересохранить */ } }
   ```
   Никакого MD5/SHA1/«соль своими руками». Никакого хэша пароля преподавателя в HTML или JS —
   клиент вообще не должен знать, как проверяется пароль.
2. **Сессия:** `session_start()` с `cookie_httponly=1`, `cookie_samesite=Lax`, `cookie_secure=1` при HTTPS,
   `use_strict_mode=1`, `gc_maxlifetime` ~ 8 часов (уроки длятся долго), регенерация `session_id()` после входа.
3. **Файл БД — вне веб-корня.** Документ-рут портала `/web/kurs`, БД в `/kurs-data/kurs.db`,
   путь задаётся в одном месте — `lib/config.php` (`KURS_DB`). Если админ настаивает на БД внутри корня:
   каталог `data/` с `.htaccess` (`Require all denied` / `Deny from all`) **и** блок `location ~ ^/kurs/data/ { deny all; }`
   для nginx-порта Web Station. По умолчанию считать, что Web Station работает на Apache 2.4.
4. **Права на диске:** каталог с БД должен быть доступен на запись системному пользователю веб-сервера
   (`http` в DSM). Дать `chmod 770` + группу `http`, владельца — пользователь, под которым работает Web Station.
   Каталог с PHP-файлами — только чтение. В `README-DEPLOY.md` расписать точные команды SSH
   (`sudo chown -R http:http /volume1/kurs-data && sudo chmod 770 …`), а также что проверить в
   **Панель управления → Web Station → PHP → профиль → разрешения** и **open_basedir**
   (если `open_basedir` ограничивает профиль, добавить в него путь к каталогу БД, иначе PDO не откроет файл).
5. **Лимит подбора:** счётчик `failed_logins` + `locked_until` на пользователя и глобальный лимит по IP
   (таблица или файл в `/kurs-data/`), задержка ответа 300–700 мс на неудачный вход. Логи в `audit`.
6. **Роли:** `student` видит только свои данные и контент; `teacher` — всё. Каждая проверка роли —
   в начале каждого обработчика, не «где-то в общем месте».
7. **Экранирование:** все SQL — подготовленные выражения PDO; весь вывод в HTML — `esc()` (уже есть
   в `test-urok-1.html`); JSON — `json_encode` с `JSON_HEX_TAG|JSON_UNESCAPED_UNICODE`.
8. **Заголовки** (через `.htaccess` или `header()`): `X-Content-Type-Options: nosniff`,
   `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: same-origin`, `Content-Security-Policy: default-src 'self';
   img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self' 'unsafe-inline'` —
   `'unsafe-inline'` нужен, потому что существующие уроки содержат инлайн-скрипты; не ломать их.
9. **HTTPS — честно предупредить.** Web Station по умолчанию отдаёт по HTTP на порту 80: пароль летит
   открытым текстом по локальной сети. В `README-DEPLOY.md` и на странице входа (если `!$_SERVER['HTTPS']`)
   показать жёлтую плашку с двумя вариантами: (а) включить в DSM сертификат Let's Encrypt и HTTPS-порт,
   (б) принять риск изолированной школьной сети. Плашка не блокирует работу.
10. **Персональные данные детей:** хранить только фамилию/имя, класс, результаты. В `admin/README-DEPLOY.md`
    напомнить про согласие школы и про то, что БД лежит на локальном NAS и никуда не отправляется.
11. **Никаких секретов в репозитории/в архиве для загрузки.** `lib/config.php` создаётся установщиком,
    содержит путь к БД и случайный `SECRET_KEY` (32 байта, `random_bytes`) для HMAC прогресса и CSRF.

## ФРОНТЕНД-ОБОЛОЧКА

1. Страница входа/регистрации: две вкладки — «Вход» и «Регистрация». Регистрация: фамилия и имя, логин,
   пароль (показать силу, минимум задаётся в `settings`), код класса (выдаёт преподаватель). Простая капча
   не нужна, но обязательна задержка и лимит попыток.
2. Оболочка после входа: шапка (имя, класс, кнопка «Выйти»), слева — дерево:
   Урок 1 → Урок 2 → Урок 3 → Урок 4 → Тест 1…4 → Финальный проект (если открыт),
   у каждого пункта значок состояния: не начат / в работе (N из M слайдов) / пройден / тест сдан (оценка).
   Справа — iframe с контентом. Кнопки «открыть в новой вкладке» и «печать» для каждого файла.
3. **Разблокировка по порядку сохраняется**: следующий урок открывается, когда сдан тест предыдущего
   (настраивается в кабинете; по умолчанию — тест обязателен, урок доступен для чтения сразу).
4. **Синхронизация прогресса (мост).** В `_study_mode.js` добавить необязательный блок (не ломая офлайн-режим):
   ```js
   if (window.parent !== window) {
     postMessage({t:'kurs-progress', lesson:LESSON_ID, unlocked:unlocked, visited:visited,
                  position:cur, tasks_done:…, tasks_total:…}, location.origin);
   }
   ```
   Оболочка принимает сообщение, проверяет `e.origin === location.origin`, троттлит (не чаще 1 раза в 5 с
   и обязательно при `visibilitychange`/`beforeunload` через `navigator.sendBeacon`) и шлёт в `api/progress.php`.
   При входе оболочка загружает серверный прогресс и передаёт его в iframe параметром
   `?restore=<подписанный токен>`; `_study_mode.js` при наличии токена предпочитает его локальному `localStorage`.
   `LESSON_ID` подставляется сборщиком (`build_course.py` / `build_students.py`) — например `course`, `u2`, `u3`, `u4`.
5. **Офлайн-совместимость:** если `fetch` не отвечает (портал открыт с флешки), оболочка работает как сейчас —
   прогресс только в `localStorage`, тест выдаёт код результата для передачи преподавателю. Не ломать этот режим:
   существующие файлы должны продолжать работать двойным щелчком.
6. Страница теста (`test.php`) — порт движка из `test-urok-1.html`: тот же интерфейс, тот же формат кода,
   те же объяснения и разбор по темам, но вопросы приходят с сервера без ответов, а проверка — серверная.
   Вкладка «Результаты на этом компьютере» остаётся (для офлайн-попыток) + появляется автоматическая
   отправка на сервер.
7. Кабинет преподавателя (вкладки): **Журнал** (по классам, фильтр «лучшая попытка», поиск по фамилии,
   CSV/JSON/печать), **Прогресс** (кто на каком слайде застрял, heatmap по классу), **Темы**
